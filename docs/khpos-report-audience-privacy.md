# Report recipients and private reporting views

School Reports → **My reports** shows the signed-in staff member's assigned reports and their submitted history. **Reports to review** is a separate inbox for reports actually submitted to an active designated reviewer role covering the author's campus and section. A teacher with an additional leadership role can use that reviewer inbox; holding Teacher alone grants no peer access. Direct report IDs and revision-history requests use the same server checks. Never-submitted drafts and in-progress returned corrections are private to the author. They become available to the reviewer only on submission/resubmission.

Authorised report-type managers open **Report types & schedules → Edit form, audience & deadlines**. Under **Who must submit this report?**, choose **Only selected staff positions** and select the actual class teachers (or other intended submitters). Save with a reason. If the report is paused, use its status controls to activate it once the audience is correct. The app does not infer class-teacher duties from a generic Teacher role or a report's title.

Recipients must hold an active submitter-role assignment within the same school and configured campus/section. The server validates all selected IDs for both recurring generation and one-off creation; the recipient directory is available only within report managers' authority. Removed/inactive recipients no longer get unsubmitted obligations, templates or reminders. Existing draft records are retained but hidden outside the corrected audience; submitted history remains available to its current original author and designated reviewers. Staff cannot change report audiences, assign themselves, inspect peers' drafts or review their own submission.

Report types keep all-role audiences by default for backwards compatibility with legitimate role-wide reports. Editing an existing restricted type from an older client preserves its restriction. A selected audience with no recipients cannot be activated. Schedule/role/scope/reviewer changes retain their existing new-type requirement; explicit staff selection can be updated on an existing type with version checks and an audit reason. Managers' aggregate totals exclude unassigned unsubmitted obligations and do not grant access to report answers.

Incident containment: the owner-identified **Teachers Daily Reports** type had been configured for every Teacher assignment. Its role-wide schedule was paused and restricted to selected staff awaiting leadership selection. Two existing submitted reports were preserved; no reports or answers were deleted and no class-teacher identities were guessed. System containment events record the reason with a null system actor. School leadership must select the actual class teachers and reactivate the schedule.

Validation includes real migration/function tests in PGlite for selected recipients, one-off/recurring gates, denied draft/direct-ID/history access, multi-role reviewer separation, returned-correction privacy, submitted-history retention, stale type versions and school boundaries. Live read-only verification confirmed eight teacher accounts had zero peer rows in default personal views, zero peer draft visibility and zero incorrectly assigned open obligations after containment. New RPC privileges remain service-only; security/performance advisors reported no new findings.
