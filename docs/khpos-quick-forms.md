# Quick choices for school and HQ reports

School reports now render Yes/No and single choice answers as large labelled radio controls. Multiple choice questions render native checkboxes, and follow-up questions can depend on an earlier choice, including a selected checkbox. No answer defaults to a positive response. Hidden follow-up answers are excluded from saved/submitted payloads; PostgreSQL validates the visible required questions and rejects invalid, repeated or contradictory choice values.

Report managers can select Staff work update or Teacher daily update templates under Report types & schedules. They can edit the choices, required flags and follow-up conditions. New report types start with the staff quick template. Choosing a template asks before replacing the editor's questions. The selected staff audience, ownership, scope, recurrence, designated review and historical report snapshots are unchanged. Saving a changed type affects future generated requests. Existing requests retain their original form and answers, including open drafts: there is no silent conversion of school-authored narratives into assumed facts.

HQ Reporting Centre opens new submissions in quick mode: reported work status, work areas, help needed and follow-up needed. Relevant explanations appear conditionally, followed by final notes and an optional evidence reference. Unfinished/other work needs a brief explanation. The existing detailed form remains available. The server validates the choices and generates explicit *reported* summaries for existing reviewers/history, while retaining structured answers and notes in a nullable JSONB column. Returned quick submissions restore their saved selections. Returned legacy submissions keep the detailed form. Recurrence still advances once on first submission and independent review rules remain unchanged.

The same accessible choice control also replaces dropdown/ambiguous checkbox inputs for existing choice and Yes/No fields on controlled task forms. It does not redefine the schema, remove evidence requirements, rewrite approved policies, or replace safeguarding accounts, employment case narratives and approval reasons with checkboxes. Other specialist forms retain their existing inputs until their workflow can define meaningful options.

## Verification

`test-quick-forms.mjs` executes the actual migration and validates conditional questions, nested visibility, required arrays, valid options, uniqueness, exclusive none answers, old text forms, private function ACLs, client payload projection, HQ quick server rules and actual choice-control callbacks. Existing reporting privacy, delivery and lifecycle tests continue to run. Full test suite, lint, typecheck and production build are release gates. Component/SQL/HTTP checks do not establish physical-device visual acceptance.
